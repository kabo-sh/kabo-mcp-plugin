# Motion catalog: style cards and components

Generated by the runner's catalog generator (creator_remake.atoms.catalog_doc) from the runner's registries; do not
edit by hand.

## How a `motion_graphics` call is written

`inputs`: `base` (optional video: the animation is laid over it, at the base's own aspect ratio)
and `refs` (0-4 images). `params`: `duration` (0.5-120 s) and `spec`, which is one of:

- **A. Your own composition** -- `{"markup": "...", "style": "<css>", "script": "<gsap>",
  "palette": <style card id or colour object>}`. `style` here is CSS text, so a style card goes
  in `palette`; it sets the page background, text colour and font and the CSS variables
  `--mg-bg --mg-fg --mg-accent --mg-secondary --mg-muted --mg-font-display --mg-font-body`.
  Every visible, animated element has its own `id` and `class="clip"`; the script adds tweens to
  `tl` with fixed times (`DUR` is the shot length). The canvas is 1080x1920; over a `base` it
  takes the base's aspect with 1920 px on the long side (`--mg-w`, `--mg-h`).
- **B. A component** -- `{"component": "<id>", "fields": {...}, "style": <style card id or
  colour object>}`. Only the component table's fields are accepted. Every word and number on
  screen comes from `fields`; nothing is filled in for you.
- **C. An exemplar page** -- `{"exemplar": "<name>", "fields": {"PLACEHOLDER": "text", ...},
  "style": <style card id or colour object>}`. A finished multi-layer page from the exemplar
  table below, rendered as it is with your words in its placeholders: a part whose field you
  leave out is dropped, a missing required field is refused with the page's field list, and
  the page times itself to `duration`. Use it when no component fits the shot.

**Caption band.** The bottom fifth of the frame (y > 0.80) is kept for captions: components and
exemplar pages put nothing there, captions burned on a project video sit in it by default, and
your own markup keeps it free too.

A style is used only when you give one; without it the neutral default (`neutral_dark`) is
used. A colour object is `{"bg", "fg", "accent", "secondary"?, "muted"?, "font_display"?,
"font_body"?}` with `#rrggbb` colours. Use one style for the whole video. The runner also reads
`params.style` and the old `params.preset` (= `spec.component`); some hosts accept only
`spec`, `duration` and `preset`, so put the style inside `spec`.

Refs are in the composition as `ref_1.<ext>` ... `ref_N.<ext>` in the order given (also under
their own file name when that name is unique). With a `base`, only `tracked_overlay` follows
things in the video; every other component is laid over it as it is.

Errors are not covered up: a missing or unknown field, a wrong component, or a HyperFrames lint
or render error comes back as an error that names what to fix (the component's fields, or the
lint's lines). Fix the call and run it again.

## Style cards

With a reference, pick by `medium` first -- the medium and render tier written in the
reference's style definition (`reference_style`) -- then by light and texture, then by
`suits`; a style the creator names comes first. `prompt words` go into every generated
picture (`still`, `make.images`, a generated row) made for a shot in that card, so the
code layer and the pictures read as one medium.

## Components

`cannot do` says where a component stops: when the reference's picture needs more than that,
write the shot yourself (spec A) from the closest exemplar page below.

| `street_grid_map` | A route drawn across a stylised street grid, each stop popping in as the line reaches it. | A stylised grid, not a real map; 2-6 stops on one route; no geography, no second route. | `stops` | `title`, `kicker`, `subtitle` | - |
