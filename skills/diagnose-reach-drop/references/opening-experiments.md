# Opening experiments

Use shared short-video methods only when an opening experiment fits the requested next steps.
Read the method catalog from the first command below, then the details of one feasible mode.
Use only these commands and this page; do not open the files under `references/hook-core/`.

```bash
python3 '<skill directory>/scripts/prepare_traffic_hook.py' --platform <platform> --output '<run directory>/hook-methods.json'
python3 '<skill directory>/scripts/prepare_traffic_hook.py' --platform <platform> --pattern-id <Mxx> --output '<run directory>/hook-opening-<Mxx>.json'
```

Write the proposed opening in a next step's `opening`: a concrete first picture, the exact first
line or intended sound/silence, what the two convey together, and the materials it needs (owned or
authorised; unprovided proof is a preparation need). Include it only when supplied content
identifies the subject and promised result; otherwise request the topic or a sample. A tutorial
subject or material description supplies a proposed demonstration, not an observed defect of the
published video; only observed media supports claims about actual first pictures or sound.

The test changes one variable against a control and keeps the other picture/sound choices
comparable; a combined rewrite is one package test, not evidence for either component. Methods do
not establish traffic causation, restriction or platform rules. Keep mode IDs, method names and
helper mechanics out of creator-facing text. Skip this path for long video, image posts,
source-share arithmetic or audience questions.
