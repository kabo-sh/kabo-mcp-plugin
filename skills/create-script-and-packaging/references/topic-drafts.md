# Draft a selected topic without inventing confirmed inputs

Use this route when the user has supplied or selected a concrete topic and asks
for creative script, packaging or scoped copy work, but has not confirmed an audience, goal
or desired audience action required by the native direct-selection builder.
Reuse established conversation facts first. An account handle or a request to
write about an unspecified product is not a concrete topic.

Distinguish a missing fact from a creative choice. A request to design a script
can authorize proposing its framing or CTA; it does not confirm those proposals
as facts about the creator. When a usable draft is possible, write it from the
selected topic, known constraints and missing facts. Deliver the draft now, instead of only asking the user to choose a route
or inventing confirmed fields to enter the native pipeline.

## Preserve the requested deliverable

- Give the entire requested script, not a synopsis or a sample opening. For a
  full package, include the requested hooks, spoken copy, scene/visual and
  on-screen directions, title/cover brief, caption or description, and CTA.
  For a scoped title or opening edit, preserve the existing script and use its
  scoped edit contract instead of expanding into a full package.
- Label proposed audience, creative angle and CTA as proposals. Keep an
  explicit user choice authoritative. A simple engagement CTA may be proposed
  where appropriate; do not invent a downloadable checklist, discount,
  customer result, product capability or delivery promise to make it persuasive.
  For a course, consultation or service, do not imply lessons, templates,
  coaching, handoff, bonuses or other offer contents unless the user supplied
  them. Use a neutral CTA (for example, invite a question or a follow) or mark
  the offer details as placeholders.
- Keep missing factual material visible at the affected line. Ask one short
  question batch for information that changes the content, proof or ability to
  film. If the missing material is the topic, source story or actual event the
  user asks to reproduce, ask for it instead of substituting a generic draft.
- Preserve explicit production constraints throughout copy and directions. A
  one-take/no-editing brief must be performable in one take; do not make cuts,
  B-roll, captions or post-production mandatory. Offer optional alternatives
  separately from the requested executable version.
- Apply the same evidence, originality and claim boundaries as the native
  package. Creative permission does not establish health effects, personal
  experience or customer outcomes. Do not add such claims merely to produce
  a stronger hook. Where proof is absent, use a clearly qualified proposal or
  a visible placeholder rather than presenting an unsupported assertion.
  For maternal, medical, nutrition or exercise topics, do not state a causal,
  diagnostic, treatment or postpartum-safety claim without supplied evidence
  and appropriate qualification. Replace unsupported advice with an observed
  question, a clearly labelled hypothesis, or a prompt to verify with a
  qualified professional; do not use a health claim as a hook merely because
  it sounds more compelling.
- For a hook, opening or CTA rewrite request, return every requested variant
  and placement recommendation in the same response. Do not replace the copy
  with a research plan, account analysis or a request to observe metrics first.
  Do not import an unrelated account, offer or audience from earlier context
  unless the current request explicitly identifies it.
- Treat a scoped CTA rewrite as a deliverable-first contract: before any
  rationale, experiment plan or metric advice, output a labelled table with one
  row per requested CTA variant. Each row must contain the exact copy, the
  recommended placement (for example, opening, mid-roll transition, payoff,
  or closing), and a short use note. If the user does not specify a count,
  provide at least five distinct variants. A plan to test CTAs is optional
  follow-up content and never satisfies the copy-and-placement request.
- Preserve explicit length and language, including relevant preceding turns.
  If duration is absent, use the existing duration-planning guidance and
  relevant available context; identify estimates as estimates. A draft route
  is not permission to truncate a requested complete long-form script.

## Keep confirmation and execution separate

Do not call `build_direct_selected_idea.py` with proposed audience, goal or CTA
as confirmed input. Do not manufacture `SelectedIdea`, `input_snapshot`,
approval or provenance records for this route. Label the result as a creative
draft with any remaining production conditions; never claim that it is a
validated `ScriptPackage`, approved for production, a finished cover image or
an uploaded/published artifact.

When the user confirms the missing choices and requests the native package,
reuse the draft and the confirmed choices, then run the ordinary builder,
validators and renderer. If the original request already supplies those inputs
or explicitly requires validated package artifacts, preserve that native path;
do not replace it with prose to save time. A final review checks all requested
sections, source constraints, factual gaps and production limits, not just the
presence of a draft label.
